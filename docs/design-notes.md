# 设计笔记：为什么长这样

本工具包的每条纪律都对应社区里一个真实的失败案例或长期实践。这里记录调研中
最有分量的证据和取舍理由，方便你判断哪些规则可以按自己情况改、哪些最好别动。

信源：Karpathy [原始 gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
与 [v2 提案](https://gist.github.com/rohitg00/2067ab416f7bbe447c1977edaaa681e2)及两者评论区、
Hacker News 讨论串、多个开源实现的 issue 与作者自述、数篇长期使用复盘
（三个月每日使用 147 页库、六项目 192 页库、两个 1300+ 文件的生产库工程笔记）。

## 五条核心实证

1. **150–200 页是无索引方案的上下文天花板**。三个月复盘（147 页/约 200 次查询）：
   过线后 agent 开始忘记页面存在、重复建页。某 3k star 实现的用户在 623 页时
   68% 页面从索引失联、212 条断链。这是分级检索阈值（100/150/300）的依据。
2. **活下来的部署全部保留人工复核**。全自动维护的案例几个月内都出现同样退化：
   自信的错误互相引用、矛盾累积快于解决。被验证可行的自动化形态只有一种：
   自动起草 + 人工放行。
3. **写在 prose 里的规则不会被执行**。唯一天天自用的作者自承：守则写了没用，
   最后全部下沉成脚本门禁。所以本包能用代码判断的检查都在 `scripts/`。
4. **批量 ingest 是错误放大器**。实测有库单日爆增 707 页、一周烧掉数亿 token
   （成本大头是链接已有页和矛盾复查的反复读取）。所以单批限 10 个文件、
   每批停下复核、单独 commit。
5. **log 和 index 是最先失控的文件**。两个生产库中最长的文件都是它们。
   所以 log 有行数观察线，index 只做目录不做正文。

## v2 提案九个升级点的裁决

| v2 建议 | 裁决 | 理由 |
|---|---|---|
| supersession（推翻不删除） | 采纳 | 评论区共识「显式取代优于衰减曲线」，长期实践验证 |
| 记忆分层 | 采纳（映射） | capture=工作记忆、log/会话索引=情景、wiki=语义，不另建目录 |
| 遗忘曲线 | 拆两半 | 测量交给脚本（冷度看板），执行留给人；无人反馈「自动衰减好用」 |
| 事件驱动自动摄入 | 改为提议 | 全自动案例全部退化；开工提醒 + 人确认是可行形态 |
| 数值置信度 | 拒绝 | 评论区批为 false precision；证据链（来源+日期+行内引用）替代 |
| 知识图谱后端 | 拒绝 | 生态里无人真上图库；typed wikilink + Dataview 覆盖绝大多数需求 |
| 混合检索 | 阈值制 | 100 页内 grep 够用（4 个独立信源）；跨线再升级，不预建 |
| self-healing | 限结构性 | 断链回填这类确定性操作可自动；语义问题只报告 |
| 多 agent 协作 | 拒绝 | 单人库无此需求；Claude/Codex 先后接力已被生产库验证可行 |

## 独立收敛现象

四个互不知情的实现（本包、一个企业级实现、一个流传较广的 Skill、一个 PM 插件）
在这些设计上给出了同一组答案：可信度分级标注、类型化链接、脚本+AI 双层校验、
专职工作流文件。互不抄袭还长一样，说明它们是这类系统的结构性约束，不是偏好。

## 页面类型：entities / concepts / synthesis

三分出自 Karpathy 原版的页面类型学，也是各实现的最大公约数。真正必要的只有
synthesis 单列：你的判断需要别的页面不需要的纪律（写推理过程、行内溯源、
被推翻走 supersession）。entities 和 concepts 只是方便浏览的粗桶。
库超过百页嫌目录碍事，可以压平成 flat + frontmatter type，成本只是 git mv。

另一条值得记住的界线（来自一位维护 4000+ 笔记两年的批评者）：蒸馏别人的材料
得到的是参考库，蒸馏自己的思考才有复利。synthesis 空着是正常状态，
靠 LLM 把它填满才是病。配套的 /review 间隔重复，是把「你自己得思考」
这件事机制化的另一半。

这条界线不是新观点，它的理论源头是 Zettelkasten（卢曼卡片盒），近年的普及读本是
Sönke Ahrens 的《How to Take Smart Notes》：用自己的话重写才发生理解，卡片之间的
连接是思考本身而非检索索引。值得注意的是它在 LLM 时代被反复独立重新发现——上面那位
批评者、以及一位做 AI+Obsidian 分享的创作者（读完这本书才想通「一直把 AI 放错了位置」，
她的判断是「AI 搭的第二大脑很快吃灰，因为笔记不是我写的、线也不是我连的」），
彼此不知情却给出同一结论。三方独立收敛，说明它是这类系统的结构性约束，不是个人口味。

对应到本包的取舍：agent 负责搬运与体力活（读原文、查重、建链接、跑体检），
synthesis 页的判断必须你自己下，这也是「进 wiki 必须过人」这条纪律在认知层面的理由，
而不只是质量控制。

## 长期使用者的共同细节

- 入口触发句写进 agent 必读文件（没有它 wiki 就是死重）
- log 同时承担查重职责（agent 建页前先看历史）
- 缺口盘点：定期对比原料和 wiki，把 known unknowns 显式列出来
- 每批入库单独 commit，效果不好整批回滚
- 维护是真实负担（每 2–3 周约半小时），低频高质好过每天自动
