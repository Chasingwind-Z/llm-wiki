# /distill — 把本次会话的精华蒸馏进 capture/drafts（不碰 wiki）

回顾**当前这次会话**（从头到现在），提取值得沉淀进知识库的内容，写成一份草稿放进
`capture/drafts/`。这是采集动作，不是 ingest：**绝对不要读写 `kb/*/wiki/` 下的任何文件。**

## 步骤

1. 通读本次会话，挑出 **3–5 个**值得长期保留的点。只要这几类：
   - 做出的**判断/决策**（以及为什么这么定、排除了什么）
   - 得到验证的**结论/事实**（附它的依据来自哪）
   - **被否掉的方案**和否掉的理由（防止以后重走弯路）
   - 踩到的**坑**和绕法
   不要收：过程性闲聊、一次性的操作细节、没有结论的开放讨论。

2. 把候选清单（每条一行：类型 + 一句话概括）展示给用户，**一次性确认**：
   哪些要、哪些不要。不要逐条反复问。

3. 确认后写**一个**文件：`capture/drafts/YYYY-MM-DD-<主题slug>.md`，格式：

   ```markdown
   ---
   source: conversation
   date: YYYY-MM-DD
   status: draft          # 由后续 /ingest 复核后才可能进 wiki
   suggested_kb: <分类名或 null>   # 建议归属分类，仅供参考
   ---
   # <主题>

   ## <每个点一个小节>
   <内容本身 + 一句"依据/上下文"，让三个月后的读者不需要原会话也能懂>
   ```

4. 报告写入路径，提醒：这只是草稿，进 wiki 需在下次 `/ingest` 时由用户复核。

## 边界

- 一次会话最多产出一个 draft 文件；没有值得沉淀的内容就直说"本次没有"，不要硬凑。
- `suggested_kb` 只能从现有 `kb/` 下的分类里选，没有合适的就写 null——**不许自创新分类**。
- 会话里已经写进某个文件/文档的内容不要重复沉淀，写一行指针即可。
